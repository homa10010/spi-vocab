# SPI言語対策アプリ 設計書

- 作成日：2026-11-02
- 対象：自分専用のスマホ学習アプリ（熟語の意味・英単語）

## 1. 目的と成功条件

**目的**：SPI・玉手箱・TG-WEB などの就活適性検査の言語分野に向けて、熟語の意味と英単語を大量に解いて網羅する。

**成功条件**
- スマホのホーム画面から起動して、通学中などのスキマ時間に片手で解ける
- 熟語系 約1500語、英単語 約3000語を収録し、全ステージをクリアすれば頻出語をほぼ押さえられる
- 覚えた語を、忘れかけた頃に自動で再出題して定着させる
- 電波のない場所でも動く

**前提（ユーザーと合意済み）**
- 使うのは本人だけ。アカウント機能や端末間の同期は付けない
- 問題文・意味・選択肢はすべてオリジナルで作る。市販の問題集や辞書の文章は写さない
- SPIには公式の出題語リストがないため、「網羅」は「頻出レベルの語を大量に収録する」ことを指す

**対象外（今回は作らない）**
- 例文、音声読み上げ
- 二語の関係、語句の用法、文の並べ替え、長文読解などの他形式
- 同意語・反意語などのSPI英語検査（ENG）独自の形式
- 本番を模した時間制限つきの模試

## 2. 出題形式

| モード | 問題 | 選択肢 | 範囲 |
|---|---|---|---|
| 熟語 | 意味の説明文（例：「おおよその見当で計算すること」） | 熟語5択 | 二字熟語・和語/言い回し・四字熟語・ことわざ |
| 英単語 | 英単語（品詞つき） | 日本語の意味4択 | SPI英語・玉手箱英語レベル |

回答直後に正誤を色で示し、**すべての選択肢の読み・意味**を表示する（英単語では各選択肢の日本語訳に対応する英単語も表示する）。

## 3. 収録語と並び順

### 熟語系（1500語・15ステージ）

| 種類 | 語数 | ステージ |
|---|---|---|
| 二字熟語 | 900 | 1〜9 |
| 和語・慣用的な言い回し | 200 | 10〜11 |
| 四字熟語 | 200 | 12〜13 |
| ことわざ | 200 | 14〜15 |

本番に一番多く出る二字熟語から始める。種類ごとに、レベル1（基本）→ 2 → 3（難しい）の順に並べる。

### 英単語（3000語・30ステージ）

| レベル | 目安 | 語数 | ステージ |
|---|---|---|---|
| 1 | 英検準2級〜2級（高校基本） | 1000 | 1〜10 |
| 2 | 英検2級〜TOEIC 700前後（ビジネス頻出） | 1200 | 11〜22 |
| 3 | 英検準1級前後（難しい語） | 800 | 23〜30 |

レベルの目安は一般的な語彙の難易度にもとづく想定で、公式基準ではない。

## 4. 画面構成

1. **ホーム**：「熟語」「英単語」のタブ。タブごとに「今日の学習」ボタン（復習n問＋新しい語m問）、ステージ進捗（例：4/15）、苦手な語の数、連続学習日数を表示する
2. **ステージ一覧**：各ステージの状態（未開放・学習中・クリア）と正答率。開放済みのステージを選んで練習できる
3. **問題画面**：上部に進捗バー（8/32）。選択肢はタップしやすい大きさ（高さ48px以上）にし、片手で押せるよう画面の下半分に置く。回答後は正誤と全選択肢の意味を出し、「次へ」で進む
4. **結果画面**：正答数・正答率、間違えた語の一覧
5. **苦手リスト**：苦手な語の一覧と、まとめて解き直すボタン
6. **設定**：1日の新しい語の数（10・20・30、初期値20）、バックアップの書き出し・読み込み、モードごとの進捗リセット

学習の途中でアプリを閉じても、次に開いたときに続きから再開できる。

## 5. 学習ロジック

### 5.1 1語ごとの記録

```ts
type WordProgress = {
  box: number;         // 0=未出題, 1〜5=覚え具合
  due: string;         // 次に出す日（YYYY-MM-DD）
  correct: number;     // 正解回数
  wrong: number;       // 不正解回数
  lastCorrect: boolean;// 直近の回答が正解か
  weak: boolean;       // 苦手リストに入っているか
};
```

### 5.2 再出題の間隔

| box | 次に出すまで |
|---|---|
| 1 | 1日後 |
| 2 | 3日後 |
| 3 | 7日後 |
| 4 | 14日後 |
| 5 | 30日後 |

- **正解**：box を1つ上げ（最大5）、表の日数後に出す。苦手な語は box が3以上になったら苦手リストから外す
- **不正解**：box を1に戻し、翌日に出す。苦手リストに入れる。同じ学習の中で、3問後にもう一度出す（1回のみ。この再出題の結果は記録に反映しない）
- 日付の切り替わりは**午前4時**にする。深夜の学習を前日分として扱うため

### 5.3 「今日の学習」の組み立て

1. **復習**：次に出す日が今日以前の語を、日付の古い順に最大100問
2. **新しい語**：開放済みのステージの中で番号が一番小さいステージから、未出題の語を設定数（初期値20）だけ取る
3. 復習と新しい語をまとめてシャッフルして出題する

現在のステージの語をすべて出題済みなのにクリアしていない場合、新しい語は0問になる。その場合はホームに「ステージ〇を練習してクリアしよう」と案内を出す。

### 5.4 ステージのクリア

- ステージ内の100語がすべて出題済みで、かつ**直近の回答が正解の語が80%以上**になったらクリアにする
- クリアすると次のステージが開く。ステージ1は最初から開いている
- **ステージ練習**（ステージ一覧から開始）は20問。未出題の語 → 直近で不正解の語 → それ以外の順に選ぶ。結果は5.2の記録に反映する

### 5.5 誤答選択肢の作り方

熟語は4つ、英単語は3つの誤答を、次の順に選ぶ。

1. その語の `confusers`（字や意味が紛らわしいが、意味は違う語）
2. 足りなければ、同じ種類・同じレベルの語からランダムに（英単語は同じ品詞を優先する）
3. それでも足りなければ、同じモードの全語からランダムに

**除外する語**：正解の語そのもの、その語の `synonyms`、意味の文字列が正解と同じ語。誤答どうしの重複も除く。選択肢は毎回シャッフルする。

## 6. データ

### 6.1 形式

```jsonc
// 熟語
{
  "id": "jk-0001",
  "type": "二字熟語",   // 二字熟語 | 和語 | 四字熟語 | ことわざ
  "word": "概算",
  "reading": "がいさん",
  "meaning": "おおよその見当で計算すること",
  "level": 1,
  "confusers": ["jk-0042"],
  "synonyms": []
}
// 英単語
{
  "id": "en-0001",
  "word": "acquire",
  "pos": "動詞",        // 名詞 | 動詞 | 形容詞 | 副詞 | その他
  "meaning": "得る、習得する",
  "level": 1,
  "confusers": ["en-0120"],
  "synonyms": []
}
```

### 6.2 ファイル構成

- `src/data/jukugo/stage-01.json` 〜 `stage-15.json`、`src/data/english/stage-01.json` 〜 `stage-30.json`
- **1ファイル＝1ステージ＝100語**。ファイル内の並び順が、そのステージでの出題順の基準になる
- 全データをアプリに同梱する（合計で約1MB、圧縮後は数百KB）。オフラインでも全語を使える

### 6.3 データ作成の進め方

1. 300語（3ステージ分）ずつ作る
2. チェック用のスクリプト `npm run check-data` を通す
3. 意味の正確さ、紛らわしい語の妥当さ、同義語の漏れを、作り手が1語ずつ見直す
4. 本人がアプリで解いてみて、気になった語を報告し、修正する

### 6.4 自動チェックの内容

- IDの重複、見出し語の重複（同じモード内）
- 必須項目の欠け、`type`・`pos`・`level` の値が正しいか
- `confusers`・`synonyms` に書いたIDが実在するか
- `confusers` と `synonyms` に同じ語が入っていないか
- `synonyms` が双方向に書かれているか（AがBを同義語にしたら、BもAを同義語にする）
- 各ファイルが100語ちょうどで、IDが連番になっているか
- 全語について、5.5の手順で必要な数の誤答を作れるか

## 7. 保存とバックアップ

- 進捗はブラウザの localStorage に保存する。キーは `spi-vocab-progress-v1`
- 保存する中身：`{ version, settings, progress: { jukugo: {id: WordProgress}, english: {...} }, stats: { streak, lastStudyDay }, session }`
- 起動時に `navigator.storage.persist()` で、ブラウザに保存データを消さないよう依頼する
- **バックアップ**：設定画面から、進捗をJSONファイルとして書き出す。読み込み時は形式を確かめ、確認画面を出してから上書きする
- **iPhoneの注意**：Safariとホーム画面のアプリでは保存場所が別になる。最初にホーム画面へ追加し、学習はホーム画面から開いたアプリで行う。この案内を初回起動時に表示する

### エラー時の扱い

- 保存データが壊れていて読めないとき：壊れたデータを別のキーに退避し、新しい状態で起動して、その旨を表示する
- データ更新で消えた語の進捗：無視する（表示や集計に含めない）
- バックアップのファイルが不正なとき：読み込まず、理由を表示する
- 保存形式を変えるときは `version` を上げ、移行の処理を書く

## 8. 技術構成

- React ＋ Vite ＋ TypeScript
- PWA：`vite-plugin-pwa` で全ファイルを事前にキャッシュし、オフラインで動かす。ホーム画面アイコンとアプリ名を設定する
- 公開：GitHub Pages。GitHub Actions で「テスト → データチェック → ビルド → 公開」を自動で行う
- 状態管理：React の標準機能（useReducer と Context）のみ。外部ライブラリは使わない

### フォルダ構成（予定）

```
src/
  data/          単語データ（JSON）
  logic/         画面に依存しない処理（ここを重点的にテストする）
    srs.ts         再出題の間隔と記録の更新
    session.ts     今日の学習・ステージ練習の組み立て
    distractors.ts 誤答選択肢の作成
    stages.ts      ステージの開放とクリア判定
    storage.ts     保存・読み込み・移行・バックアップ
    day.ts         午前4時区切りの日付計算
  screens/       各画面
  components/    ボタンや進捗バーなどの部品
scripts/
  check-data.ts  データの自動チェック
```

## 9. テスト

- **単体テスト（Vitest）**：`logic/` 以下の全モジュール
  - 再出題：正解・不正解ごとの box と次に出す日、午前4時の区切り
  - 誤答：正解が必ず含まれる、選択肢の数が正しい、同義語が混ざらない、重複しない
  - ステージ：80%の境目、全語出題済みの条件、次ステージの開放
  - 保存：壊れたデータの退避、バックアップの読み込み検証、版の移行
- **データチェック**：6.4 の内容。GitHub Actions で毎回実行する
- **実機確認**：iPhoneまたはAndroidで、ホーム画面への追加、オフライン起動、途中再開、バックアップの往復を確かめる
